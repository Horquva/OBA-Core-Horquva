## What I did today

Before making any prompts or diagrams, I wanted to learn how good AI chat tools work.

I looked at tools like ChatGPT, Copilot, and Perplexity.

I wanted to know simple things like:

- How does the AI say hello?
- What does it do when it does not understand?
- Does it remember what I said before?

Below is what I learned, split into easy topics.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/message-circle.svg" width="18" style="vertical-align:middle" /> 1. Good chat design

A good AI chat should feel like talking to a helpful person, not filling a form.

It should:

- Understand what the user wants
- Only ask questions when really needed
- Remember what the user already said
- Give short answers, not long paragraphs
- Be honest that it is an AI

**Simple rule I learned:** only use a chat if it makes the task *easier*. If a normal screen works better, use that instead.

**What this means for us:** WOBA should not turn everything into a chat. Only use chat where it truly helps.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/brain.svg" width="18" style="vertical-align:middle" /> 2. Understanding what the user wants

Old chat bots only understood exact words.

New AI systems understand the *meaning* behind the words, not just the words.

Good AI also shares helpful information on its own sometimes, without waiting to be asked.

**What this means for us:** WOBA should feel smart and helpful, but not pushy.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/database.svg" width="18" style="vertical-align:middle" /> 3. Memory — the most important part

This was the most useful thing I learned today.

AI does **not** remember anything by default.

If a user says "what about tomorrow?" and the AI does not have the earlier message, it will not understand.

| Memory Type | What It Means |
|---|---|
| Working memory | What is happening right now, in this chat |
| Episodic memory | Things said in earlier chats |
| Long-term memory | Facts and preferences that do not change often |

When a chat becomes very long, older messages get turned into a short summary. This saves space but keeps the important parts.

**Biggest mistake to avoid:** the AI quietly forgetting something the user already said. This makes users stop trusting the tool.

**What this means for us:** we must clearly decide what WOBA remembers in one chat, and what it remembers across many chats.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/layout-panel-left.svg" width="18" style="vertical-align:middle" /> 4. Copilot-style tools

A "copilot" works *with* the user, not instead of the user.

A good copilot understands:

- The user's role
- What the user is currently doing
- What the user asked before

**What this means for us:** WOBA should feel like a helpful coworker, not just a search bar.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/rocket.svg" width="18" style="vertical-align:middle" /> 5. Starting to use the tool (Onboarding)

Many good AI tools today skip long welcome tours.

Instead, the user sees the real tool right away and starts using it.

The main goal is called **time-to-first-value**.

This simply means: *how fast can the user get something useful?*

**What this means for us:** WOBA should let users ask a real question quickly. But since WOBA is used by executives, we still need to build some trust early, for example by showing it is safe and accurate.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/git-fork.svg" width="18" style="vertical-align:middle" /> 6. Long conversations

A chat does not fail at just one message. It usually fails somewhere in the middle of a long conversation.

Things that can happen:

- The user changes their mind
- The user gives an unclear answer
- The user switches topics

**What this means for us:** our flow diagrams in Day 3 must show these situations, not just the easy path.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/shield-check.svg" width="18" style="vertical-align:middle" /> 7. Trust and clear answers

Trust is not built in one day. It grows slowly, based on how the AI behaves over time.

Good AI tools usually offer a **"Why this?"** button. This shows the reason behind an answer, without forcing the user to read it every time.

It also helps to clearly show:

- What is generated by AI
- What is real, verified data

**What this means for us:** since WOBA is used for important decisions, every answer should be easy to check and explain.

---

## <img src="https://unpkg.com/lucide-static@latest/icons/list-checks.svg" width="18" style="vertical-align:middle" /> Summary — what I will carry into Day 2

| Idea | Why It Matters |
|---|---|
| Never forget context silently | Builds trust |
| Show short answers first, details on request | Keeps it simple |
| Get to value fast, but stay trustworthy | Executives need both |
| Separate AI answers from real data | Keeps things clear |
| Use chat only when it helps | Avoids annoying the user |
| Design for messy conversations too | Real usage is not perfect |
