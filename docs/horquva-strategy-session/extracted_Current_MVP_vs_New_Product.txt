Horquva — Current MVP vs New Product Design

Sep 30, 2026 · @Affan Ahmed

The new product design keeps the current MVP's strongest ideas (the dependency map, what-if simulations, succession, ownership and the chat agent) and narrows them to one job: when someone leaves, nothing breaks. It goes from 17 pages to 7, from a demo organisation to real company data, and from scores to counted, evidence-backed facts. The new product is a proposal; its scope is not yet signed off.

5. How it is done better

The biggest gains come from how the product works, not from any one screen.

Area

Current approach

New approach

Why it is better

Focus

Many questions across 17 pages

One promise, one buyer, one moment (a departure)

Easy to explain and to sell; every feature serves the same loop

Data

Loaded dataset

Discovered from the customer's systems, then confirmed by owners

Findings are about the customer's real organisation

Trust

Computed values

Every fact carries its evidence state and source

A buyer can check any number back to where it came from

Unknowns

Treated by the model

Shown as unknown and counted separately

The product never claims more than it knows

Computation

Many engines and modules

One deterministic rule set, computed once in the backend

Same data, same answer on every screen, PDF and chat reply

Headline

Index score

Counted fact with a drill-down to named assets

Understood without a legend

People

Individual views and scores

Holdings per person, coverage per team, no scores

Fits the EU AI Act and US positioning; safer for HR to adopt

AI

Agent over the data

Assistant that explains only, using the same API and linking evidence

Answers always match the screens

Outcome

Insight

Action: handover pack, successors, tracking, post-departure check

Ends with the problem fixed, not just seen

Access

Internal data

Read-only, metadata-only; never reads messages; disclosed where a key can't be limited

Easier security review for customers

Growth

Broad feature set at once

Build in slices: v0 → v1 → v1.1 → v2, each gated

Each release is tested with buyers before the next
