Horquva — Software Requirements Specification (v0 to v2)

Sep 30, 2026 · @Affan Ahmed

1. Introduction

This SRS defines what Horquva v0 (free n8n Ownership Check) and v1 (the Continuity Platform) must do in full, and v1.1 and v2 at a lighter level (section 7). It is a draft: the product scope it is built on (revision 3, 30 Sep 2026) is not yet signed off, and no buyer has validated it. Treat every requirement as a proposal that discovery calls and the hands-on API test may change.

Audience: the two engineers building Horquva, and the founder for sign-off.

How to read requirements. Each has an ID (AREA-nn), a release (v0, v1, v1.1) and a priority: Must (release cannot ship without it), Should (planned, can slip), Could (only if time allows). "Shall" marks a binding requirement.

1.1 Definitions

Term

Meaning

Asset

Anything a person can hold: an automation (n8n workflow), an app, a group, a credential, or a CSV-imported system, vendor or process

Holder / owner

The person accountable for an asset

Fact

One attribute of an asset: owner, backup, criticality, documented, fallback, depends-on, runs-on-credentials-of

Evidence state

How a fact is known: stated (from an API), inferred (derived by rule), confirmed (by a person), unknown

Departure

A person leaving or changing role, with a leave date

Handover pack

Everything a departing person holds, what breaks, and who takes over

Confirmation campaign

A batch of requests asking owners to confirm facts no API provides

Successor

The person named to take over an asset

Directory

Microsoft Entra ID or Google Workspace

2. Overall description

Horquva is organisational continuity software: when someone leaves, nothing breaks. It discovers who holds what across a company, asks owners to confirm what no API knows, and runs a handover before each departure and a check after it. AI automations (n8n first) are the entry point, not the whole product.

2.1 Target customer and buyer

Customer: companies of 100–2,000 people on Microsoft 365 or Google Workspace, adopting AI automation, using n8n and OpenAI and/or Anthropic.

Buyer: whoever owns offboarding and the automation rollout: Head of Operations, IT lead, or AI/automation lead. (Open: which of the three leads.)

2.2 User roles

Role

Who

Can do

IT lead or Ops lead running Horquva

Connect sources, manage users and roles, launch campaigns, enter departures, see everything, export

2.3 Operating environment

Web app, current Chrome, Edge, Safari and Firefox, desktop first. Confirmation forms must also work on a phone.

One deployment per customer (single tenant). No multi-org in v1.

Connects outbound to n8n (Cloud or self-hosted and reachable), Microsoft Graph or Google Admin SDK, OpenAI and Anthropic admin APIs.

2.4 Constraints

Two engineers; v1 estimated at about 4.5–5 months (38.5–41 engineer-weeks, unverified).

Built from scratch. The old OBA Core codebase is reference only; no code or engines carried over.

Deterministic core: every finding is computed by rules from data. AI only explains; it never computes a finding.

Read-only, metadata-only access to customer systems.

2.5 Assumptions (to be tested)

Buyers feel this pain enough to pay (untested: no calls yet).

Owners will complete confirmation requests.

A meaningful share of Entra apps and groups have owners set.

n8n node parameters expose which AI model each node calls.

3. System context and core loop

Every feature serves one step of the loop: discover → confirm → watch → hand over → verify. Sources are read only; findings are computed by rules; AI only explains them.

System context · 4 sources, 5-step loop, 4 outputs

Connectors discover what they can. Owners confirm the facts no API provides (backup, criticality, documentation, fallback). Handover is the centre of the product.

6. Scope boundaries and open questions

6.1 Out of scope for v1

Any 0–100 score, health index, pillar, maturity or benchmark.

Scoring or ranking individuals; predicting who will leave.

Forecasts and probability ranges (v2, only once accuracy is measured).

Reading message content.

Writing to customer systems, including one-click reassignment (v2, opt-in).

AI-drafted handover documents (v2).

Distribution lists, on-premises-synced groups, Google app ownership (no API).

Custom-code agents with no platform behind them (CSV only).

Multi-org, real-time sync, SOC 2.

The old engines: eIRWR, the hand-written Bayesian score, the 55 brain modules.
